# Frozen local balance baseline policies
Source integration:167cc746eacd1cad3542967e65950e2b0a943db4. No core tuning or repository changes.

Existing policies inspected:src/cli/evaluation.ts ships a generic harness, not ordinary/expert policies. Prior external smoke policy bought first affordable offers, filled cells, and rarely reasoned about composition; it had no sales or strategic reserve. Its skilled variant only reordered offers and placement. Those do not satisfy this comparison.

Both new policies are deterministic and use only detached public observation/rules. policies.mjs imports no core, filesystem, RNG or private match state. The driver alone knows seed/state/log. No policy accesses future draws, allocator, replay, seed or RNG. Public rule odds are used only to value material acquisition, never to peek at results. No future wave schedule is read. Seed101/102 were used for eight functional smoke runs, then policy frozen before requested seed1..100. Some requested seeds1/3/7 had appeared in earlier smoke work; this is not a pristine blind held-out experiment.

Shared competence: deploy strongest bench units to free cells using sampled path coverage and support adjacency; at full board replace a substantially weaker unit by swap; recognize exact character/star triples and previewed automatic chains; consider distinct-tag synergy; sell only benched star1 non-pair material to release a full bench or fund a currently visible pair completion. Every accepted action re-observes. No deliberate rejection farming or infinite sell/reroll loops.

Normal hypothesis: one visible purchase at a time; rank role-adjusted damage rate per price, matching copies, immediate upgrades and missing synergy definitions; refresh only when at least refresh plus cheapest recruit is affordable. Basic competence, not a random novice.

Expert hypothesis: value field/bench inventory and discounted partial-star pipelines; compare the current visible offer followed by one other currently visible affordable offer, using a pure hypothetical inventory projection; score gain per combined cost. With at least10 board units reject low-value purchases and reserve one additional minimum recruit before refresh. Material option value uses published rarity probability/pool size and partial1/2-star copies. This is a shallow two-purchase heuristic, NOT solved optimal play, hidden-RNG search or proven human skill. It may underperform the normal policy; that is evidence about the heuristic, not proof that strategic play is worse.

Approximate value: star damage multiplier, attack period, hand-set role factors(multi1.7/splash2.2/slow1.6/support1.5/bossFirst1.35), board top16 plus12% bench value, capped distinct-tag diversity, and discounted incomplete triple value. Assumptions may misvalue situational splash/slow/support, cooldowns and synergy of benched material. Two-step hypothetical purchase simulates only inventory triple counts, not full combat or placement trajectory. No tuning on the400 observed outcomes is permitted within this run.

Equal conditions: both count40/count80 profiles × normal/expert × same seeds1..100;12starting coins and identical profile-defined schedules/stats. Profiles differ in count limit/warning. Actions consume the same gameplay RNG stream, so differing reroll counts change later shops: paired seeds are common initial conditions, not identical realized offers.

Metrics: clear rate with100 denominator; failure reason/wave; first2/3-star wave with missing counts and achiever-only median; accepted purchase/reroll/sale/move/swap counts; maximum bench occupancy and full-bench wave starts; idle gold at starts; ticks×50ms combat time (preparation/thinking time excluded); all400 replay/hash roundtrips. Wall-clock execution is not player duration. Complete JSON replays stored per run. Approximate-policy results do not establish human fun, final balance, rarity value or three-star2x2 behavior.
