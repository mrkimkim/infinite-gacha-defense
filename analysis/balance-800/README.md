## 자료와 재현

각 폴더의 REPORT/POLICY/REVISION은 실행 당시의 체크포인트입니다. 당시의 '미게시/미병합' 문구는 이 자료를 공개하는 현재 상태와 구분합니다. `results.csv`는 검색 가능한 핵심 개별 결과, `results.json.gz`는 원본 전체 결과이며 `data-manifest.json`에 원본/압축 SHA256이 있습니다. `summary.json`은 당시 집계입니다. wave-structure-analysis에는 웨이브 집계와 실제4개 잔존 상태가 있습니다.

정책 파일은 실행 당시 원본 바이트를 유지했습니다. run/check의 import 경로와 구조 분석의 데이터 루트만 이 경로에 맞췄습니다. 원본 manifest의 정책 SHA를 확인하세요. run 스크립트는 코어와 같은 저장소의 Node24.19+에서 실행합니다. 기존 replays 원자료는 로컬 보존되어 있고 이 경로에 모두 업로드하지 않았습니다. 아래 재실행으로 생성할 수 있습니다. 출력 파일을 덮어쓸 수 있으므로 별도 checkout에서 실행하세요.

```sh
mkdir -p analysis/balance-800/balance-baseline-400/replays analysis/balance-800/balance-revision-101-200/replays
node analysis/balance-800/balance-baseline-400/run.mjs
node analysis/balance-800/balance-revision-101-200/run.mjs
python3 analysis/balance-800/wave-structure-analysis/analyze.py
```

같은 seed라도 정책의 리롤에 따라 이후 RNG 소비와 상점이 다릅니다. 전투 시간은 준비/생각 시간을 포함하지 않습니다. 101/102는 이전 기능 smoke에 노출됐습니다. 인간 재미·실제 모바일 성능·최종 밸런스 증거가 아닙니다.

## 구조 검토의 두 실험 제안

1. 보스600tick 마감은 유지하고 최종 일반 적 정리 마감을 분리하는 제한 실험. finalTimeout만 제거하면 기존 duration 보상이 잔존몹을 둔 채 승리시킬 수 있으므로 최종 보상 조건까지 함께 검증해야 합니다. 추가 대기/잔존 HP/패인을 함께 측정해야 합니다.
2. wave20을 다음 고정 사이클로 넘어가는 보스 관문으로 만드는 별도 연속 생존 모드 실험. 이후 웨이브·경제·종료 기준부터 정의해야 하며 기존 유한20웨이브 승률과 직접 비교하면 안 됩니다.

이800경기 자료에는 두 실험 구현이 없습니다. 후속 G 유예 실험은 별도 로컬 브랜치에서만 수행하며 이 분석 브랜치/배포에 포함하지 않습니다.
