# playable-v2 구현 경계와 실험 계약

상태: 후속 합의 반영, **현재 SHA의 두 독립 DOT 재리뷰 대기**. 코드 구현·밸런스 검증 완료가 아니다.
owner 리더 / assignment_generation 1 / branch `leader/playable-v2-contract`.
기준 main `a9273ea3597fbfb9730ca3bd653fdf5241b27f28`. 원장은 [Issue #21][issue].

## 1. 루프와 조작

4×4 보드에서 영입 → 벤치 → 편성/시너지 → 전투 성장 → 판매/XP 이전 → 리롤/승급으로 다음 전투 대응을 바꾼다. 배치8/벤치8, 별·레벨과 무관하게 기물당1칸이다.

- 구매·리롤·이동·교환·합성·판매·책·시작은 준비 단계 전용. 전투 편성은 잠기고 준비의 적·효과·cooldown·시간은 정지한다. 다음 전투는 수동 시작이며 출전0은 거부한다.
- 상점3칸은 최초 및 다음 준비 진입마다1회 무료 전체갱신. 구매는 빈 벤치 필수, 구매칸은 비우고 즉시 보충하지 않는다. 유료 리롤은 전체갱신, 잠금 없음. 1성 후보를 slot0→1→2 균등 독립추첨하며 첫 상점도 중복 허용한다. 구매 RNG 소비0.
- 같은 캐릭터·같은 별의 서로 다른3ID를 명시 합성한다. keepId는 입력에 포함되어야 하며 결과는 그 위치의 새ID다. XP 합계를 보존하고3성은 합성하지 않는다. 포화 벤치의 자동합성 구매 예외는 없다.
- 판매는 기물 제거·코인·책 생성을 원자 처리한다. 책 XP는 `floor(xp×80/100)`,0이면 생성하지 않고 수량상한은 없다. 책 사용은 전체 XP 이전과 책 삭제를 한 번에 수행한다. 킬 코인은 없다.
- 전투 시작 출전ID를 고정한다. 성공 전환 시 웨이브 XP 예산을 n명에게 정수 균등분배하고 나머지는 unitId 오름차순 배분한다. 벤치 XP 없음, n=0 방어 시 예산 소멸. 최종 성공도 XP/코인을1회 지급한 결과를 기록하고 실패는 미지급한다. 다음 준비의 무료갱신은 전환당1회다.
- 레벨은 누적 정수 XP의 파생값이며 레벨 상한에서도 XP를 보존한다. 합성/책 사용의 총 XP는 보존, 판매의 명시된 내림 손실만 감소, 전투 보상 외 총 XP 증가는 금지한다.

## 2. 시간·타깃·피해

50ms tick, 총20웨이브, 보스5/10/15/20. 일반 최대400tick, 보스 최대600tick이다. 마지막 예정 스폰 소진+생존 적0이면 조기 준비 전환 또는 최종 승리한다. 미래 스폰을 생략하거나 다음 전투를 자동 시작하지 않는다.

5/10/15는 보스가 기한 안에 죽었으면 구간 끝에 일반 잔존을 다음 준비로 이월한다.20은 기한 내 일반 적까지 전부 제거해야 한다. 보스가 준비로 이월되지는 않는다. 잔존 수는 보스 포함이며 `count >= limit`이면 즉시 패배, 유예 없음. 경고는 limit의80%부터다.

첫 advance는 logical tick1을 처리한다. 각 처리 tick의 순서는 다음과 같고 이벤트 timestamp도 같은 logical tick을 사용한다.

1. `expireAt <= tick`인 효과 만료.
2. 예정 스폰.
3. unitId 오름차순으로 각 유닛의 cooldown 감소/공격, 공격 직후 사망 제거.
4. 생존 적 이동.
5. 잔존 수 패배 판정.
6. 보스/최종 기한 실패 판정.
7. 조기 또는 최대 구간 성공 전환·보상.

`deadline=600`은600번째 공격·사망 정리·이동까지 처리한 뒤 판정한다. 따라서 해당 공격으로 보스/마지막 적을 잡으면 기한 실패를 피할 수 있다. 경로의 화면 modulo 위치와 누적 이동 거리는 분리한다.

일반 타깃은 사거리 내 누적거리 내림차순, 동률 enemyId 오름차순이다. 보스 특화는 사거리 내 보스를 먼저 고른다. 각 유닛의 다중/범위 공격은 그 공격 직전 정렬된 대상 스냅샷으로 처리하고 즉시 사망 제거하여 뒤 유닛이 죽은 적을 다시 선택하지 않게 한다. 범위는 화면 좌표 거리로 판정한다. 범위 대상 배열의 세부 정렬/경계 연산은 공동 API 체크포인트에서 고정한다.

피해는 기본×별×Lv×시너지×해당 보스 배율의 **전체 유리수 곱을 한 번만 내림**, 최소1이다. 중간 배율마다 내리지 않는다. 실제 hit damage는 대상 남은HP 이하로 clamp한다. 각 정수 곱의 안전 범위를 검사한다. 별/Lv는 피해만 성장시키며 사거리·둔화·지원 강도는 성장시키지 않는다.

cooldown은 해당 tick에 먼저 `max(0, cooldown−1)`로 감소한 뒤0이면 공격 가능하다. 공격하면 적용 주기로 새 cooldown을 설정하고 같은 tick에 다시 감소/재공격하지 않는다. 예: 신규 cooldown0이 tick1에 주기12로 공격하면 tick2에서11, tick12에서1, tick13에서0이 되어 다음 공격한다(간격12tick). 신규 영입0, 합성은 입력 최대 잔여값 승계, 준비·이동·교환·책으로 리셋하지 않는다. 버프는 다음 공격 직후 새 주기에만 적용하며 기존 잔여값은 소급 재계산하지 않는다.

## 3. 실험 프로필과 역할 데이터

경제A/B × 잔존40/80의 네 조합을 버전 고정 rulesId/digest로 구분한다. 기능 연결은 A부터 진행하는 데 세 의견이 모였다. **production 기본값과 난도는 미검증**이며 비교 후 선택한다.

| 항목 | 실험값 |
|---|---|
| 시작 / 판매1·2·3성 / XP 회수 | 12코인 / 1·3·9코인 / 80% 내림 |
| 경제A 영입·리롤·웨이브보상 | 2·1·6 |
| 경제B 영입·리롤·웨이브보상 | 3·2·4 |
| 잔존 한계·경고 | 40·32 또는80·64 |
| 별 피해 배율 / Lv 피해 | 100·220·484% / `100+8×(Lv−1)`% |
| 최대Lv / 누적 XP 경계 | 10 / `[0,8,24,48,80,120,168,224,288,360]` |
| 웨이브 XP 예산 | `16+2w`, w=1..20 |

일반적 수 `6+w`, HP `12+4w+floor(w²/4)`는 리더의 **미확정 스폰 가설**이다. 스폰 시각·이속·보스 데이터와 함께 코어 프로필 체크포인트에서 확인하며 기존 v1 값을 암묵 승계하지 않는다.

다음은 [최신 역할 절충안][roles]과 [모모 동의][role-ack]의 실험 데이터다. **키키의 이 절충안에 대한 최신 동의는 아직 확인되지 않아 역할·시너지 채택만 pending**이다. 캐릭터 이름은 이번 게임용 매핑이며 원작 능력이나 외형/아트 공개 승인이 아니다. 좌표1칸=1000.

| 캐릭터 | 피해 / 주기tick / 사거리 | 자동 행동 |
|---|---|---|
| 포포 | 6 / 12 / 3200 | 빠른 단일 투사체 |
| 누리 | 5 / 24 / 3000 | 주 타깃 주변 반경1100의 모든 적에 범위 공격 |
| 루루 | 대상당3 / 10 / 2200 | 서로 다른 최대2대상에 독립2발, 적1명이면1발 |
| 도도 | 3 / 20 / 3000 | 단일 피해와 이동속도30% 감소40tick |
| 모모 | 3 / 20 / 2800 | 단일 공격+인접4방향 아군 공격주기10% 단축 |
| 토리 | 10 / 30 / 4500 | 보스 우선, 보스 피해×2, 없으면 일반 타깃 |

지원은 자신/벤치 제외, 동종 중첩 없음. 새 주기는 `max(1, floor(기본주기×90/100))`. 집중(포포·루루·토리)은 피해, 협력(누리·도도·모모)은 사거리 +5/+10%를 **해당 태그 기물에만** 준다. 출전 고유 캐릭터2/3명 기준이며 중복/별/벤치는 수를 더하지 않는다. 준비 명령 후 파생 시너지/오라를 표시한다.

둔화 중첩은 강도를 합산하지 않는 방향이다. 서로 다른 강도의 만료 후 약한 효과 복귀/폐기, 동일 강도 만료 갱신, 보스 저항 수치, 사거리 정수 반올림은 역할/API 체크포인트에서 고정할 남은 세부 데이터다.

## 4. 공유 API 원칙

technical-v1의 exported API·schema1·canonical17키와 기존 bytes/hash/리플레이 해석을 유지한다. 새 규칙은 별도 v2 진입점·schema2·고정 rulesId/digest로 격리하고 브라우저/Node가 같은 TypeScript 코어를 사용한다. 기존 전역 규칙을 바꾸거나 임의 데이터 주입으로 digest를 우회하지 않는다.

준비 명령은 `recruit`, `reroll`, `move`, `swap`, `merge`, `sell`, `useBook`, `startWave`. pause/restart는 어댑터 기능이며 새 경기는 createMatch로 시작한다. 명령의 ID·재화·공간 검증 및 적용은 원자적이다. 거절 시 ID/코인/책/RNG/로그 불변. 비정상 advance·안전정수 overflow도 사전 검증/복제 상태로 처리하여 부분 진행을 반환하지 않는다.

observe는 분리된 readonly 관측이다. 필수 항목은 배치/벤치/상점/책, 별·Lv·현재XP·다음경계/상한, 실효 피해·사거리·활성 시너지, 잔존 수·한계/경고, 구간 시간/보스 마감, 예정XP·판매 코인/회수XP, 준비/결과의 잔존 적과 효과다. RNG/seed/다음ID/미래 랜덤후보/acceptedLog는 정책 관측에 노출하지 않는다. 다음 웨이브 예고는 공개 고정 패턴만 제공한다. UI가 계산식이나 진행 권한을 복제하지 않는다.

**정확한 타입·명령 오류 우선순위·이벤트/리플레이 shape·canonical키는 모모 소유 src/core-v2의 첫 공동 API 체크포인트에서 고정한다.** 두 어댑터는 그 API를 import하기 전 추측으로 구현하지 않는다. [API 스케치][api]는 검토 입력이며 문서에 타입을 중복 정의하지 않는다.

## 5. 수용 기준

- 정확성: v1 과거 fixture/seed1 UI 로그 회귀, v2 Node↔브라우저 canonical/hash/로그와 batching 일치, strict 입력·프로필 검사 및 실패 원자성.
- 경제/XP: 매매·합성·책 재사용 복제 금지, 상한Lv XP 보존, 벤치/배치 한계, 빈 슬롯 구매, 무료갱신/보상 중복 금지, 거절 RNG 불변.
- 전투: tick1/효과만료/600번째 공격, count 경계·동일tick 처치, 예정 스폰 전 조기종료 금지, 최종 잔존 실패, cooldown 실제 간격, 준비 완전 정지, 공격 스냅샷/실제 hit damage 검사.
- 정책: 일반/숙련 모두 같은 공개 관측만 사용한다. 일반을 무작위 초보로 약화하지 않으며 숙련 탐색 RNG는 경기 RNG와 분리한다. 경제2×한계2, 조정/검증 seed 분리, 프로필별500경기를 첫 검증 목표로 삼는다. 정책ID·seed·리플레이와 역할전환/첫2·3성/유효행동/유휴웨이브/벤치포화/코인/대기/보스실패/편성다양성을 기록한다. 같은 seed도 리롤 횟수에 따라 상점 경험이 다름을 명시한다. 집중XP·복제지원·재사용 stress는 별도 집계한다.
- 화면: 짧은 높이에서 보드/벤치/핵심조작·잔존/보스시간 동시 확인, 별과 Lv/XP 분리, 사거리·공격/피격·판매회수·거절이유 표시, 접힌 시너지의 활성단계 표시. 실제 viewport는 웹 수용 체크포인트에서 고정한다.
- 세 독립 DOT가 실제 화면의 성장 루프와6역할 구분·승패/재시작을 플레이하고 정확한 SHA로 교차 리뷰한다. 봇 승률·브라우저 조작을 사람의 재미 평가로 부르지 않는다. 정확성 결함은 통과시키지 않는다.
