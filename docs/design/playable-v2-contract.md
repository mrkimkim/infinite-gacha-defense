## 1. 목표와 판정 방식

4×4 정면 보드에서 영입 → 벤치 → 편성/시너지 → 전투 성장 → 판매/XP 이전 → 리롤/승급으로 다음 전투의 선택이 바뀌는 첫 완결 루프를 만든다.
가희 가챠 상점 모티프와 승인된 정면 콘셉트를 출발점으로 삼되 기존 게임 규칙·에셋은 자동 승계하지 않는다.
새 규칙의 브라우저와 Node CLI는 같은 TypeScript 로직을 사용한다.

- **공통 경계**: 세 닷의 의견이 수렴한 설계 방향. 이 문서 SHA의 리뷰나 구현 승인을 뜻하지 않는다.
- **조정 제안**: 일부 동의 또는 한 명의 상세안. 미응답을 동의로 세지 않는다.
- **실험 후보**: 비교할 숫자/데이터. 기본값이나 밸런스 확정이 아니다.
- **미확정**: 구현 전에 명시할 경계/API/데이터. 작성자가 빈칸을 임의 결정하지 않는다.

리더·모모·키키는 설계·아트·구현·테스트·리뷰에 동등하게 참여한다. 아래 캐릭터 역할은 팀의 영구 직군 배정이 아니다.

## 3. 최신 조정 제안과 미확정 경계

### 준비·상점·편성

- **S3+S5+S7 공통 경계**: 구매 슬롯은 비우고 즉시 보충하지 않는다. 준비 진입 때 전체3칸 갱신, 유료 리롤도 전체3칸 갱신. 모든 갱신은 균등 독립 추첨이며 중복 허용.
- **S3 상세안**: 최초 준비에도 무료갱신은1회만, slot0→1→2 추첨, 1성만 판매, 거절 명령 RNG 소비0회. 슬롯 잠금은 S2에서 제외 가능, S3–S4에서 제외 제안.
- **S2+S3 상세안**: 영입은 벤치 빈칸 필수. 포화 상태의 자동합성 예외 없음. 구매 후 직접 배치하고 명시적 합성으로 공간을 만든다.
- **미확정**: 이동/교환의 보드↔벤치 조합, 같은 위치 명령, 잘못된 ID, 합성 입력의 위치 혼합, 가득 찬 공간에서 결과 위치 검증 순서. API와 오류 목록에 명시해야 한다.

### 시간·패배·승리

- **S3+S5+S7 공통 시간 후보**: 일반20초/보스30초, 보스 기한은 해당 전투 구간 끝. 살아 있는 보스를 다음 준비로 넘기지 않는다. 마지막은 같은30초 안에 모든 적을 정리한다.
- **미해결 이견**: S5는 일반 조기 전멸에도20초 유지와 다음 패턴 표시, S7은 마지막 예정 스폰 소진+적0이면 조기 준비 진입을 제안한다. 자동 다음전투나 미래 스폰 생략은 허용하지 않는 방향이다. S7은 최종 조기 승리도 제안하며 S6도 마지막 예정 스폰 소진을 요구한다. 5/10/15 보스 처치 뒤 일반적은 구간 끝에 이월 가능,20은 기한 내 전체 정리라는 S7 상세안도 확인한다.
- **S2 제안**: 잔존 한계80%부터 경고. S3의40/32와 S4의80/64는 이 비율에 맞는 후보다.
- **S3 타깃 제안**: 누적거리 내림차순, 동률ID 오름차순. 오래 산 탱커 집중의 부작용을 시험하고 보스우선 패시브는 별도 정의한다.
- **미확정**: tick 길이/경계 포함 여부, 이동·패시브·스폰의 세부 순서, 보스 조기 처치 후 비최종 구간 종료, 최종 조기 전멸 시 즉시 승리 여부, 마지막 tick의 전멸/카운트/보상 우선순위. 시간 후보를 기존 tick 수로 조용히 환산하지 않는다.

### XP·합성·판매의 원자성

- **S3 상세안**: 전투 시작 출전명단 스냅샷을 기준으로 성공 전환 때 XP를1회 지급. 출전0이면 예산 소멸(S4도 적립하지 않음). 이는 빈 보드로 시작을 허용한다는 합의가 아니다.
- **S2 상세안**: 실패 웨이브에는 XP를 지급하지 않는다. 최종 승리의 지급 여부/시점은 계약 리뷰에서 명시한다.
- **S2+S3 상세안**: 합성 결과는 keepId의 위치에 새ID, 3성은 합성불가. S3은 전역 nextEntityId 사용을 제안하며 keepId는 위치 선택에만 사용한다.
- **S1+S2 원자성 제안**: 판매와 책 사용은 고유 ID를 검증한 원자 거래. 거절하면 재화/RNG/로그를 바꾸지 않는다. 같은 책을 반복 사용하거나 판매 명령 재전송으로 복제할 수 없어야 한다.
- 회수 XP는 `floor(유닛 XP × 회수율)` 제안. S3은 XP0이면 책을 만들지 않는 안이다. 책 수량 상한과 책 합치기 여부는 미확정이며 상한을 두어도 코인만 지급되고 책이 사라지는 부분 성공을 허용하지 않는다(S2).
- 검증 원칙 제안: `모든 유닛 XP 합 + 모든 책 XP 합`은 전투 보상 외에 증가하지 않는다. 합성/책 사용은 보존, 판매는 명시된 내림 손실만 감소. 레벨 상한은 XP 폐기를 뜻하지 않는다. 향후 XP 상한을 도입하려면 폐기량을 UI/이벤트와 계약에 명시한다.

## 6. API와 재현성 — 모모 스케치 검토 중

모모의 [API 스케치 S6][s6]가 게시되었다. 아래는 모모 제안의 요약이며 서명·shape·파일 경로와 schema를 최종 확정하지 않는다.

- 별도 v2 진입점(예시 `src/core-v2/index.ts`), schemaVersion2, 프로필별 rulesId/digest. v1 exported API/schema1/canonical17키 유지.
- 동기 함수군 `createMatch`, `dispatch`, `advance`, `observe`, `getRules`, `canonicalState`, `stateHash`, `replay`, `pathPosition`, `boardPosition`. 정확한 unknown 입력/반환 shape는 S6를 원문으로 리뷰한다.
- 준비 전용 명령 `recruit`, `reroll`, `move`, `swap`, `merge`, `sell`, `useBook`, `startWave`. 구매는 RNG0/슬롯null, 책은 전체 사용, 책 상한 없음/XP0 생성금지 제안. pause/restart는 어댑터 기능.
- 유닛/적/책 공통 nextEntityId, 출전명단 고정, 지속효과 만료tick canonical 포함. 파생 레벨/시너지/판매예고 등은 observe의 detached readonly snapshot에서 제공. UI에 공식을 복제하지 않는다.
- 거절은 입력 동일참조 및 ID/코인/책/RNG/로그 불변, replay 전체 입력 사전 검증/partial state 금지. 실험 프로필마다 별도 digest.
- 50ms tick/일반400·보스600은 제안. 준비 advance 거부, 빈 보드 startWave 거부, 실패 보상 없음, 최종 성공 보상 포함 선호. 효과만료→스폰→공격→이동→처치정리→판정은 아직 선후 확인 필요.

**API 미확정 핵심**: 6역할 효과/시너지 계산순, 피해/XP 반올림, cooldown의 준비·합성 보존, 최종 종료/보상 순서, 조기 전멸 처리. S6의 구체 명령 검증도 두 동료의 현재 문서 SHA 확인 전까지 제안으로 취급한다.

API 검토에서 필요한 목록:

1. v1/v2 진입점과 프로필 선택, 기존 호출의 기본 동작 유지 여부. 기존 전역 RULE_DATA/SCHEMA_VERSION 결합을 어떻게 분리할지.
2. 준비/전투/종료 상태, 출전 스냅샷, 유닛/캐릭터/책 ID와 결정적 발급, shop 빈칸, 별/XP/파생 레벨의 표현.
3. 구매/리롤/이동/교환/합성/판매/책/시작의 입력 검증·거절 코드·원자성과 RNG/로그 소비.
4. 시간 단위, tick 판정 순서, 성공/실패/마지막 정리 전환과 XP·코인 지급 이벤트.
5. 버전 고정 데이터와 digest 연결, canonical 직렬화/해시/리플레이 검증. 임의 외부 데이터 주입으로 digest를 우회하지 않도록 하는 S4 제안.

technical-v1의 기존 fixture 및 seed1 실제 UI 로그의 canonical/hash 회귀를 유지한다(S3). 현재 문서는 v2가 구현되었거나 해당 회귀를 실행했다는 증거가 아니다.

## 7. 구현 전 리뷰와 이후 검증

이 문서의 현재 SHA를 모모·키키가 각각 실제 읽고 공통 경계·조정안·미확정 분류를 확인해야 한다. API 스케치와 남은 경계, 실험의 제한 범위/기준을 확인한 뒤 리더가 별도 owner·세대·비중첩 파일 범위를 배정한다. 기존 구현 담당 이력은 v2 담당 확정이 아니다.

후속 검증 계획(미실시):

- 결정성: 같은 seed/명령의 Node·브라우저 상태/해시/로그 대조, v1 과거 리플레이 회귀, 프로필 불일치 거절.
- 원자성: 판매/책 재사용, 벤치 포화, 잘못된 합성 입력, 전투 중 모든 성장 명령, RNG/로그 불변, XP 총량 보존/명시 손실.
- 시간: limit−1/limit 경계, 스폰과 같은 tick 처치, 마감 tick 보스 처치, 최종 보스 이후 일반적 잔존, 준비 중 완전 정지, 보상 중복 없음.
- 정책 시뮬레이션: 일반/숙련 가설 정책과 집중육성 악용 후보를 같은 seed로 비교. 정책 정의와 결과·리플레이를 기록.
- 실제 화면: 세 독립 DOT가 각자 핵심 행동부터 승패/재시작까지 플레이하고 정확한 SHA·입력·관찰을 남긴 뒤 교차 리뷰. 브라우저 조작과 봇 시뮬레이션은 사람의 재미 평가를 대신하지 않는다.
