# [기획 2] 교차 검토와 최소 수직 슬라이스 결정

미게시 초안. 기획 1의 세 독립 초안을 고정한 뒤 진행합니다.
각 닷은 다른 두 제안에서 실제 확인한 산출물을 적고 장점·우려·대안을 제시합니다. 주요 규칙·아트 방향은 두 동료 검토를 받습니다. 공통 결정 라운드 하나로 모으며 첫 답변을 복사하지 않습니다.

일상 설계 논쟁은 두 라운드 뒤 진행 방식을 점검합니다. 팀이 합의한 비교 기준과 범위·시간·성공 기준이 제한된 실험을 사용합니다. 되돌릴 수 있는 실험 기본안도 팀의 명시적 동의가 필요합니다. 필수 리뷰·증거는 부재나 침묵으로 면제되지 않습니다.

완료 기준: 최소 시작→결과→재시작 슬라이스, 공유 TypeScript/Node 결정성 및 경로/스키마의 검증 범위, 수락 기준, 제외 범위를 기록. 기록에는 팀의 합의·채택 이유·이견·실험·재검토 조건을 남깁니다. 리더에게 단독 설계 결정권은 없으며 중요한 미해결 사안은 리더를 통해 사용자에게 전달합니다.
구현은 시작 게이트가 열린 뒤 리더가 별도 Issue에 owner·세대·파일 범위·base를 배정합니다.

사용자는 리더와만 소통합니다. 동료의 배정·질문·확인·리뷰·진행·차단 보고는 GitHub의 검증된 Issue/PR에서 리더를 통해 처리합니다. 모모·키키는 사용자에게 메시지 중계나 자료 전달을 요구하지 않습니다. 리더가 사용자 판단 사항을 모아 질문하고 답을 GitHub에 전달합니다. 최초 접속 자체가 불가능하면 연결 차단으로 기록하며 동료가 연결되었다고 가정하지 않습니다.

리더·모모·키키의 설계·아트 의견과 토론 권한은 동등합니다. 리더의 추가 권한은 조율·배정·일정 운영뿐이며, 자신의 제안에 우선권을 주거나 설계를 단독 결정하지 않습니다. 일정 결정을 빌려 콘텐츠를 결정하지 않습니다. 합의한 비교 기준과 실험으로 이견을 다루고, 중요한 미해결 사안은 리더가 사용자에게 모아 전달합니다. 팀이 명시적으로 동의한 되돌릴 수 있는 실험 기본안을 사용할 수 있으며, 끝없는 만장일치를 강제하거나 침묵을 동의로 간주하지 않습니다.
