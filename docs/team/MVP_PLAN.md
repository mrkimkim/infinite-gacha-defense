# MVP 제안
상태: 세 닷 검토 전 제안. 확정된 게임 규칙이 아닙니다.

## 승인된 출발점
가희의 가챠 상점 모티프와 정면 4×4 정사각형 콘셉트 이미지가 출발점입니다. 이미지 실물은 아직 이 준비 작업에서 확인하지 않았습니다.
기존 infinite-gacha의 규칙, GDD, 27개 에셋은 선택적 참고입니다.

## 첫 마일스톤
1. 동일 참고 이미지를 실제 확인하고 리더·모모·키키가 독립 제안 하나씩 작성.
2. 초안 고정 후 두 동료의 교차 검토.
3. 리더가 근거·이견을 기록하고 제한된 실험으로 최소 수직 슬라이스 선택.
4. 시작 게이트와 공동 규칙/스키마 합의 뒤에만 구현 작업 배정.

첫 슬라이스는 시작 → 최소 모집/배치 → 실제 경로 이동·전투 → 결과 → 재시작을 연결하는 후보입니다. 구체 유닛 수·웨이브 수·성장 단계는 공동 선택합니다.

## 제안하는 MVP 범위
- 브라우저에서 시작부터 결과까지 한 경기를 완주하고 다시 플레이.
- 4×4 배치 구역을 둘러싼 실제 닫힌 정사각형 경로. 네 변·모서리·마지막 구간에서 시작 구간 연결까지 구현·검증.
- 브라우저와 Node CLI가 동일한 결정적 TypeScript 엔진을 사용. 렌더링·입력과 로직 분리.
- seed, 명령열, 규칙/스키마 버전, 상태 요약이 있는 재현 가능한 리플레이.
- 안정적인 데이터 스키마: 식별자, 좌표/경로, 유닛/적, 경기 상태, 명령, 결과 및 버전 정책을 합의.
- 모집·배치·전투·성장 규칙을 세 닷이 선택. 웨이브 수, 캐릭터, 보유/배치 상한, 특성, 성장 수치는 미정.
- 승인된 일관된 모듈형 아트와 후보/제작용 분리 및 manifest.
- seed 기반 일반/숙련 봇. 행동 정책 차이를 명시하며 둘 모두 같은 공개 명령 API 사용.
- CI의 결정성/리플레이·경로·규칙 검증과 실제 브라우저 플레이 증거.

## 유한한 완료 기준(공동 승인 시 확정)
1. 승인된 최소 규칙/스키마와 구현 범위가 결정 기록에 고정됨.
2. 브라우저 시작→결과→재시작을 완주한 실제 조작 기록 1건 이상과 실패/패배 경로 검증.
3. 합의한 고정 seed 회귀 세트에서 브라우저/Node 엔진의 동일 명령 결과·최종 상태 해시 일치.
4. 4×4 배치 유효성, 경로의 네 변/네 모서리/폐곡선 연결, 모집·전투·성장 핵심 불변식 검증.
5. 일반/숙련 봇의 seed·정책·결과·리플레이 보고서. 승률을 재미의 증거로 오인하지 않음.
6. 실제 사람 플레이 피드백 1회 이상 확보하고 주요 이해/조작 문제의 처리 결과 기록. 미실시이면 미완료.
7. 제작용 에셋 전부 출처/권리·manifest·필수 리뷰 완료.
8. 최종 커밋의 CI 통과, 필요한 독립 리뷰, 미해결 고위험 차단 요소 없음, 알려진 제한 문서화.
9. 승인된 병합 후 main에서도 시작/완주/재시작 및 결정성 확인.
이 수락 기준은 반복 횟수를 무한히 늘리는 근거가 아닙니다. 범위 확대는 새 제안으로 분리합니다.

## 이번 MVP에서 제외
멀티플레이, 결제, 모바일 스토어 출시, Unity 이식. Unity 재작성 가능성을 열어두되 현재 구현 범위에 포함하지 않습니다.

## 추가 완료 기준
10. 실제 통합 SHA의 테스트·플레이 증거를 첨부해 verified 상태에 도달.
11. 리더·모모·키키가 각각 독립 기획 제안, 실제 에셋 후보, 브라우저 게임플레이 증거, 동료 리뷰를 하나 이상 제출. 미참여를 대리 기록하지 않음.
