## 전송 오류와 메타데이터 정정

초기 게시 blob `a3d8eadbca03ee20b37c34f17e7d5441de3d180f`은 전송 중 잘린 파일이었습니다. 복구 전 main의 파일은 786,445 bytes, SHA-256 `8b7a13cba742638198a3ba06598d9161d636970b7be8a34167323e3aa83293fa`였으며 전체 PNG 디코딩에서 `broken data stream when reading image file` 오류가 발생했습니다. blob 연결 확인만으로 이미지 무결성이 확인된 것은 아니었습니다.

기존 README의 SHA-256 `aaa262539399848781ea841597c70d74e59a3ff3532447fb416bfd4a2de3ff95`는 동료에게 전달된 2,734,243 bytes / RGBA 첨부 버전의 보고값입니다. 현재 Library에서 다시 받은 RGB 파일과 바이트·인코딩이 다릅니다. 그 해시를 이 기준 파일의 해시로 표기한 것은 잘못이므로 정정합니다. 전송 잘림과 두 첨부 버전의 차이는 별개의 문제입니다. 두 버전의 픽셀이 동일하다는 비교 결과도 아직 없으므로 동일 픽셀이라고 주장하지 않습니다.

복구 blob은 제한된 크기의 청크로 업로드하여 전체 길이와 로컬 계산 Git blob SHA 일치를 확인했습니다. 복구 PR에서는 원격 브랜치의 새 clone에서 파일 크기·SHA-256·Git blob SHA·전체 디코딩과 실제 이미지 열기를 다시 확인합니다. 독립 동료가 현재 커밋의 PNG를 직접 디코딩하고 픽셀을 검토하기 전에는 리뷰 승인·병합 완료로 표시하지 않습니다. 검증과 리뷰 기록은 [Issue #4](https://github.com/mrkimkim/infinite-gacha-defense/issues/4) 및 연결된 복구 PR을 따릅니다.

공개 참고 게시 승인이 제작용 전용 승인이나 일반적인 재배포 라이선스 부여를 뜻하지 않습니다. 제작용 사용은 별도 후보·권리·리뷰 절차를 따릅니다. 참고 자료 게시가 전체 킥오프 완료나 동료 리뷰 승인을 뜻하지 않습니다.
