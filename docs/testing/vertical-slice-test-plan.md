## 1. 범위와 실행 전 게이트

합의된 가역 실험은 정면 4×4, 시계방향 외곽 경로, 준비 중 무료 이동·교환, 전투 중 편성 잠금, 단일 재화, 공통 순수 TypeScript 코어, 고정 tick·seed·명령 기록이다. 첫 단면은 단일/범위 2역할, 임시 배치 상한 4, 기술 검증용 5웨이브, 적 한 바퀴 완주 시 피해 후 제거를 사용한다. 최종 MVP 분량·밸런스가 아니다.

기술 단면 뒤 동일 종류 1성 3개→2성 1개, 임시 대기석 3을 검사한다. 둔화/비중첩 인접 지원 A/B, XP 이전, 최종 누수/누적 방식·상한은 후속 실험이며 첫 단면 완료 조건에 몰래 추가하지 않는다. 참고 이미지의 80웨이브·배치8·가격·레벨 수치를 가져오지 않는다.

실행 전에 다음을 확인한다.

1. 최신 Issue 배정·세대·범위와 main SHA를 다시 읽는다. 변경/재개로 기존 배정이 무효면 리더의 새 배정까지 중단한다.
2. 승인된 계약·규칙 버전, 구현 PR head SHA, 실제 빌드/실행 SHA를 고정한다. 미합의 항목은 아래 §2로 연결한다.
3. 저장소에 실제 있는 설치·테스트·빌드 명령과 종료 코드를 기록한다. 이 문서는 아직 존재하지 않는 npm 스크립트나 테스트 파일을 실행 명령으로 꾸미지 않는다.
4. Node와 브라우저가 같은 코어/규칙/fixture를 쓰는지 확인한다. URL만 같거나 화면이 비슷한 것은 동일 빌드 증거가 아니다.
5. 사례마다 `PASS / FAIL / BLOCKED / NOT_RUN / N/A(근거)`를 기록한다. 차단은 통과로 세지 않고, 재실행은 이전 기록을 보존한다.

## 2. 계약이 고정되어야 답할 수 있는 사항

예상값을 정할 계약이 없으면 해당 사례는 `BLOCKED(C번호)`다. 예컨대 합성 결과를 임의로 첫 빈칸에 놓거나, 자동합성으로 칸이 생길 것이라 가정해 꽉 찬 영입을 허용하지 않는다. 구현을 보고 그 출력을 그대로 기대값으로 복사하는 순환 검증도 금지한다.

초안이 그대로 채택되는 경우 경계 fixture는 d=0/4999/5000/9999/10000/14999/15000/19999와 L 직전·정확·초과, 사거리/폭발 반경의 직전·정확·직후를 포함한다. 잘못된 seed·버전·digest·advance count, 유닛 없는 startWave, 준비/결과에서 advance, 첫 프로필의 merge도 거절 검사가 된다. P5의 선행 공격 처치 후 재표적·distance 동률의 ID 우선·벤치 비공격과 P7 keepId가 입력 세 ID에 없는 경우를 명시적으로 검사한다. 이는 제안 승인 후 기대값을 고정할 목록이지 현재 실행 결과가 아니다.

## 3. 최소 자동검사 묶음

아래 fixture/seed 목록은 실행 전에 버전 관리하고 두 런타임에서 공유한다. 정상 진행, 승리, 패배, 무효 입력, 경계용 작은 고정 fixture로 시작한다. 운영 규칙을 바꾼 진단 fixture는 별도로 표시한다.

| ID | 재현 절차 | 판정과 남길 증거 |
|---|---|---|
| D1 결정성 | 같은 규칙·초기 상태·seed·tick별 명령열을 Node에서 두 번, 실제 브라우저 코어에서 한 번 재생 | 각 명령 직전/직후와 매 tick의 canonical 상태·이벤트·해시가 정확 일치. 첫 불일치 tick/필드/양쪽 스냅샷 기록. 종료 해시만 비교하지 않음 |
| D2 시간 독립성 | D1을 브라우저의 서로 다른 렌더 프레임 공급/긴 프레임 조건에서 동일 시뮬레이션 tick까지 실행 | 승인된 catch-up/pause 정책에 따라 같은 tick 결정 상태 일치. advance 배치 크기가 달라 raw acceptedLog가 달라지면 실행 tick을 비교하고 차이를 명시; D1의 동일 명령/advance열 검증과 구분. 벽시계·렌더 프레임·비결정 난수가 코어 결과를 바꾸지 않음 |
| I1 무효 명령 원자성 | 없는/이미 소모한 ID, 판 밖/불법 위치, 재화 부족, 상한/대기석 초과, 잘못된 단계, malformed payload를 한 건씩 입력 | 시간 진행 없이 전후 권위 상태 deep-equal 및 해시 동일. PRNG 전체 상태/소비 카운터, next-ID, 재화, 개체/배치/대기석, HP, 보상, tick, 큐 포함. 거절 응답은 계약대로; 상태 밖 감사로그는 별도 증거 |
| I2 거절 후 정상 입력 | 정상 명령열 A와 같은 tick 사이에 무효 명령을 끼운 B를 실행 | 이후 정상 영입/발급 결과, PRNG, ID, 재화, gameplay 상태가 A/B 동일. 거절이 미래 난수를 소비하거나 시간을 밀지 않음 |
| L1 단계·종료 | 시작→준비→영입/배치/이동/교환→전투→다음 웨이브→승리, 별도 누수 fixture→패배 | 무료 이동/교환의 재화 불변, 전투 편성 잠금, 단계별 입력 허용, 승리/패배·보상 정확히 한 번. 마지막 적 처치/누수/HP 0 동시 tick은 C3/C4 기대값 사용 |
| L2 정지·재시작·반복 | 전투 중 어댑터 pause→대기→resume, 시작/웨이브 시작/영입을 빠르게 반복, 승리·패배 후 같은 seed/다른 seed 재시작과 반복 클릭 | pause 중 전투 tick·적·쿨다운·PRNG·재화 불변, resume 때 중복 진행 없음. 반복 명령은 명시된 허용/거절 정책과 비용·ID 정확 일치. 재시작은 이전 타이머/입력/보상/개체를 누출하지 않고 C3 초기 상태로 복귀. 진행 중 재시작·저장 복구는 현재 초안 범위 밖 |
| P1 칸·경로 경계 | 16칸에 각 좌표를 순회하고 바깥/중복 점유 입력, 네 모서리 전·경계·후 및 출발점 seam을 적이 통과 | 보드 칸·선택 위치 일치, 유효 칸 16개. 경로 끊김/역행/중복 처리 없음. 정확한 길이 및 경계 넘는 큰 이동량 fixture도 계약대로 |
| P2 한 바퀴 | 공격 없는 결정론적 fixture에서 완주 직전·정확 경계·경계 초과를 기록 | 한 바퀴 피해/제거 정확히 한 번, 다음 tick 재피해 없음. 같은 tick 처치와 완주 경쟁은 C4대로. 전체 경로 trace·HP 변화·제거 이벤트 보관 |
| A1 전투·위치 계측 | 동일 유닛/적·속도/seed/웨이브로 16칸을 한 칸씩 바꾸어 비교; 단일/범위 역할 각각 반복 | C5 사거리 경계·타깃·쿨다운·피해 정확성 확인. 중앙/가장자리 시간·실제 기여를 §5 방식으로 기록. 임의 밸런스 합격선 없음 |

무효 명령 전후 비교에서는 코어의 동일 논리 시점을 고정한다. 명령 처리 사이에 tick을 진행한 결과를 무변경 실패로 오인하지 않는다. PRNG나 ID를 해시에서 빼고 같다고 주장하지 않는다. 계약의 canonical 정렬만 적용하며 순서가 있는 배열을 임의 정렬해 차이를 숨기지 않는다. P8처럼 acceptedLog가 canonical에서 제외되면 전체 상태의 로그 불변/양쪽 재생 로그는 별도로 비교한다.

## 4. 실제 브라우저·이미지·사람 검증

자동 코어 재생과 실제 화면 입력을 구분한다. 첫 실행 때 게임 URL/빌드 SHA를 확인하고 클라우드 Chrome인지 다른 환경인지 명시한다.

- **B1 기본 완주:** 실제 클릭/키보드로 시작→영입→배치→무료 이동/교환→전투→승리, 별도 패배→재시작. 화면·재화·인원·체력·단계와 코어 기록의 일치, 실제 결과 화면까지 캡처한다.
- **B2 중단·반복:** 선택 취소/빈 곳 클릭, 빠른 연속 입력, 전투 편성 시도, pause/resume, 결과 화면에서 반복 시작, 새 판에 오래된 입력 유입 여부. 탭 숨김/복귀는 C3에 정의된 동작을 확인한다. UI 미정 기능은 N/A 근거를 남기고 존재한다고 가정하지 않는다.
- **B3 판과 경로:** 실제 표시 크기에서 16칸 선택/배치 hitbox, 네 모서리 및 출발 seam, 적의 한 바퀴 이동을 관찰한다. 이미지 접합 불량과 코어 경로 좌표 오류는 다른 결함으로 기록한다.
- **V1 이미지 검사:** 실제 픽셀을 본 asset ID·SHA256·크기·알파·피벗·출처를 기록한다. 정면 4×4 칸/민트 직선·네 모서리의 seam, 접지점, 체력/별/역할/선택 읽힘을 실제 합성 화면에서 확인한다. 원본·축소·확대 크기, 화면 해상도/viewport를 남긴다. 이미지 검사만으로 조작 성공을 주장하지 않는다.
- **H1 사람 플레이:** 실제 사람이 했을 때만 참여자 익명 ID, 사전 경험, 빌드 SHA, 안내 범위·플레이 시간·입력을 기록한다. 첫 배치/전투 시작을 스스로 찾는지, 패배 원인과 다음 선택을 설명하는지, 재미·혼란 피드백을 관찰과 인용으로 구분한다. 현재는 **미실시**이며 봇·닷 브라우저 조작으로 대체하지 않는다.

## 5. 위치와 정책 비교: 판별 가능한 작은 실험

### 중앙/가장자리 공격 시간

좌표가 고정되면 중앙 4칸과 외곽 12칸(그중 모서리 4칸)을 구분하고, 16칸별 원자료를 먼저 남긴다. 동일 역할·능력·적 경로/속도·명령 조건에서 위치만 바꾼다.

- 경로상 유효 표적이 사거리 안에 있는 tick 수와 시간(`tick 수 × 계약 tick 길이`)
- 사거리 내 시간 중 쿨다운/정지 등으로 실제 공격 불가능했던 tick 수와 이유
- 첫/마지막 공격 tick, 공격 횟수, 유효 적중·피해, 범위 역할의 다중 적중, 누수 수
- 각 위치 및 중앙/외곽 그룹의 최소·중앙값·최대, 중앙/외곽 비교(분모 0은 비율 대신 사유)

적이 먼저 죽어 노출 시간이 달라지는 영향을 분리한다. 경로/사거리 진단 fixture(예: 피해를 제거한 관찰용 적)를 사용하면 변경 규칙을 명시하고 정상 경기의 승률/밸런스 증거와 섞지 않는다. 그룹 평균만으로 일부 중앙 칸의 무기여를 감추지 않는다. 허용 가능한 격차와 조정은 팀이 관찰 후 결정한다.

### 무작위·일반·숙련 정책 제안

봇은 사람 유형을 흉내 낸 비교 정책이며 실제 사람/재미의 대리 증거가 아니다. 아래 정책은 계약 고정 후 정책 버전·타이브레이크·결정 간격·평가 예산을 명시해 재현 가능하게 만든다.

| 정책 | 합법적 정보/판단 | 용도 |
|---|---|---|
| 무작위 | 현재 UI에 공개된 정보로 열거한 합법 행동 중 정책용 별도 RNG로 선택 | 충돌·상한·교착 sanity check만. 게임성/난이도 기준선으로 사용하지 않음 |
| 일반 | 현재 재화·보유 유닛·보이는 능력·빈칸·현재 공개 웨이브 정보만 사용. 고정 역할 우선순위와 칸 순서, 단순 모집/배치 규칙 | 반복 가능한 단순 정책 기준선. 미래 RNG/숨은 적 목록/엔진 내부 상태 열람 금지 |
| 숙련 | 일반과 같은 공개 관측만 사용. 알려진 경로·사거리로 후보 위치의 노출 시간과 역할 겹침을 계산하고 제한된 합법 배치/교환 후보 비교 | 의도적 선택이 누수·유효 공격시간에 미치는 영향. 미래 전투/모집 RNG를 복제·재생해 최선값을 고르는 탐색 금지 |

하네스가 보관하는 경기 seed·PRNG·숨은 스폰·미래 명령은 정책 관측 객체에 전달하지 않는다. 정책용 난수는 경기 난수와 분리하고 seed를 별도 기록한다. 공개되지 않은 다음 웨이브나 모집 결과를 사용하는 순간 해당 결과는 비교에서 제외한다.

정책을 먼저 고정한 뒤 같은 경기 seed 목록·규칙·난이도로 paired 비교한다. seed 목록과 횟수, 예외/탈락 run 및 이유를 전부 기록하고 유리한 seed만 선별하지 않는다. 명령에 따라 RNG 소비가 달라지면 ‘같은 seed’가 ‘같은 모집 결과’를 뜻하지 않으므로 draw trace도 남긴다. 위치만의 비교는 동일한 합법 초기 편성 fixture로 별도 통제한다.

보고 항목은 정책별 승패/도달 웨이브/누수/HP/재화 사용·잔액/공격시간과 seed별 paired 차이다. 숙련이 모든 seed에서 이기도록 합격 조건을 만들지 않는다. 둔화/지원 A/B는 후속 승인된 규칙 버전에서 다른 조건을 고정한 뒤 실시하며 최종 선택은 열어 둔다.

## 7. 증거와 완료 기준

모든 결과는 [증거 템플릿](evidence-template.md)에 기록한다. 필수 연결은 `Issue/배정 세대 → 계약 SHA/규칙 버전 → PR head SHA → 실제 실행 SHA/빌드 → seed·명령·상태/이벤트 → 결과·증거 → 리뷰 대상 SHA → 통합/릴리스 SHA`다. 해당 단계가 없으면 빈 추정값 대신 `미생성/미실시`를 쓴다.

- **계획 완료:** 두 문서의 범위/차단/증거 구분을 리더·모모가 실제 문서 SHA에서 검토한다. 이로써 게임이 verified 되지 않는다.
- **기술 단면 검증:** 승인 계약의 적용 가능한 D/I/L/P/A 사례와 실제 B1–B3 결과를 확보한다. FAIL/BLOCKED는 해결하거나 영향·제외 판단을 명시하고 고위험 결정성 결함을 묵시 면제하지 않는다. 합성은 후속 단계가 되기 전 별도 NOT_RUN으로 남긴다.
- **통합 후:** PR에서 통과해도 실제 통합 SHA에서 요구 자동검사/브라우저 플레이를 다시 확인한다. integrated와 verified를 구분한다. 릴리스/배포가 없으면 만들거나 주장하지 않는다.
- **리뷰 유효성:** 새 구현 SHA에는 이전 승인이 유효하지 않다. 실제 동료가 이전 승인 SHA→현재 SHA diff를 읽고 현재 SHA에 재확인해야 한다. 같은 GitHub 계정 표기나 내부 보조 작업은 독립 동료 리뷰를 대신하지 않는다. 세대·범위 변경/재개 시 최신 배정도 재확인한다.

공개 증거에는 프로젝트 자료만 포함하며 토큰·사적 대화·개인 식별 정보가 드러나는 로그/캡처는 제외한다. 결과가 없으면 공란을 통과 표시로 채우지 않는다.
