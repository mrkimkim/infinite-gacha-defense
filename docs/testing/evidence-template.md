# 검증 증거 템플릿

이 파일은 기록 양식이다. 예시는 실제 검사 결과가 아니며, 현재 게임 자동검사·실제 게임 브라우저 조작·사람 플레이는 미실시다. 복사한 기록마다 실행한 부분만 채우고 `미실시 / 미생성 / 해당 없음(이유) / BLOCKED(원인)`을 명확히 남긴다. [검증 계획](vertical-slice-test-plan.md)의 사례 ID를 사용한다.

## 1. 작업·버전 연결

| 필드 | 기록 |
|---|---|
| 기록 ID / 작성자 / 실행자 / UTC 일시 | 미기입 |
| 작업 Issue / 배정 댓글 URL | 미기입 |
| owner / assignment-generation / 확인 시각 | 미기입 |
| 허용 파일·검증 범위 / 재개 승인 근거 | 미기입 |
| 지정 base SHA / 검사 직전 main SHA / 차이 영향 | 미기입 |
| 계획 문서 commit SHA / 계약 문서 commit SHA·승인 링크 | 미기입 |
| 규칙 버전·설정 / fixture 버전·해시 | 미기입 |
| 구현 PR URL / PR head SHA | 미생성 또는 미기입 |
| 실제 checkout·코어 SHA / 빌드 식별자·해시 | 미생성 또는 미기입 |
| 통합 commit SHA | 미통합 또는 미기입 |
| 릴리스 태그·SHA / 실행 URL·해당 빌드 연결 근거 | 미릴리스 또는 미기입 |
| Node / npm / OS / 브라우저 정확 버전·소유 환경 | 미기입 |
| viewport·DPR / 실행 옵션·의존성 잠금 파일 해시 | 미기입 |

같은 URL의 최신 빌드로 과거 PR을 검증했다고 쓰지 않는다. dirty tree면 diff/해시와 영향을 기록하고 깨끗한 동일 SHA 결과와 구분한다. URL/태그뿐 아니라 실제 SHA를 남긴다. 비공개 주소·토큰은 게시하지 않는다.

## 2. 요약과 증거 종류

- 목표/변경점:
- 확인한 것:
- 실패/차단/미실시:
- 다음 행동·담당·필요 결정:
- 결론 범위: 계획 검토 / 코어 검사 / 실제 브라우저 조작 / 이미지 확인 / 사람 플레이 / 통합 검증 중 해당하는 것만

| 증거 종류 | 상태 | 실제 횟수/범위 | 결과·원본 링크/해시 | 증명하지 못하는 것 |
|---|---|---|---|---|
| 정적 검사·타입 검사·빌드 | NOT_RUN | 미실시 | 없음 | native TS 실행만으로 타입 검사 통과 주장 불가 |
| 자동 코어 테스트·봇 재생 | NOT_RUN | 미실시 | 없음 | 실제 UI 조작/사람 이해·재미 |
| 실제 브라우저 입력 | NOT_RUN | 미실시 | 없음 | 사람 플레이/전체 seed 결정성 |
| 이미지 픽셀·화면 검사 | NOT_RUN | 미실시 | 없음 | 입력 성공/전투 규칙 |
| 사람 플레이 | NOT_RUN | 실제 참여자 없음 | 없음 | 봇이나 닷 조작을 사람으로 표기 불가 |

상태는 `PASS / FAIL / BLOCKED / NOT_RUN / N/A(이유)` 중 하나다. 도구가 노출됨, API가 성공함, 테스트 명령이 시작됨만으로 PASS를 쓰지 않는다.

## 3. 사례별 실행 기록

각 사례 또는 같은 입력의 paired 실행 묶음마다 아래를 반복한다.

- 사례 ID / 검증하려는 규칙 / 계약 절·SHA:
- 사전 조건·초기 상태 fixture·해시:
- 경기 seed / 정책 seed(사용 시) / 정확한 tick·sequence 포함 명령열 파일·해시:
- 실행한 명령 그대로 / 작업 디렉터리 / 옵션 / 시작·종료 UTC / 종료 코드:
- 브라우저이면 실제 클릭·키보드 순서 / URL·빌드 / pause·숨김 탭 조건:
- 기대값과 근거(구현 출력을 그대로 기대값으로 삼지 않음):
- 실제 결과 / PASS·FAIL·BLOCKED·NOT_RUN:
- stdout·stderr·스냅샷·이벤트·해시·화면 원본 링크/해시:
- 최초 불일치 tick/명령/필드 / 최소 재현 입력:
- 관련 결함 Issue / 영향 / 재검사 SHA·기록:

### 결정성·무효 명령 체크

| 검사 | Node 실행 A | Node 실행 B | 브라우저 실행 | 비교 결과 |
|---|---|---|---|---|
| 코어/규칙/fixture SHA | 미기입 | 미기입 | 미기입 | NOT_RUN |
| seed·tick별 명령열 | 미기입 | 미기입 | 미기입 | NOT_RUN |
| 명령 전후/매 tick canonical 상태·이벤트·해시 | 미기입 | 미기입 | 미기입 | NOT_RUN |
| 종료 상태·해시 / 첫 불일치 | 미기입 | 미기입 | 미기입 | NOT_RUN |

무효 명령 비교에는 같은 논리 시점의 전체 상태와 PRNG 상태/소비 횟수, next-ID, 재화, tick, 큐, 보드/대기석, HP/보상을 포함한다. 각 필드의 전후값 또는 스냅샷 diff 링크를 남긴다. 상태 외 거절 감사로그는 따로 기록한다. 무효 명령을 끼운 실행/끼우지 않은 실행의 후속 정상 결과·ID·난수 비교도 기록한다.

### 합성 체크(후속 실험)

- 입력 종류·별 / 서로 다른 세 소모 ID / 각 원래 위치:
- 결과 ID·종류·별 / 결과 위치 / 위치 선택 계약 근거:
- 전후 전체 개체 수 / 1성 재료 등가량 / 무관 개체 diff:
- 전후 재화·명시 비용 / 배치 점유·상한 / 대기석 점유·상한:
- ID·PRNG 변화 / 꽉 찬 영입·실패 합성 전후 무변경 증거:
- 중복/소모 ID 반복 입력 및 연속 클릭 결과:

## 4. 위치 계측·정책 비교

이 절은 수치 입력 양식이며 빈칸을 0으로 간주하지 않는다.

- 목적 / 사전 고정 seed 목록·횟수 / 중단·탈락 처리:
- 정상 경기인지 진단 fixture인지 / 바꾼 규칙:
- 동일하게 유지한 유닛·별·능력·적·속도·경로·웨이브·초기 재화:
- 중앙 4칸/외곽 12칸/모서리 4칸의 계약 좌표:

| 위치·역할·seed | 관찰 tick | 사거리 내 tick·시간 | 공격불가 tick·이유 | 첫/마지막 공격 | 공격·적중·피해 | 누수 |
|---|---|---|---|---|---|---|
| 미실시 | 미기입 | 미기입 | 미기입 | 미기입 | 미기입 | 미기입 |

16칸 원자료 링크, 그룹별 최소/중앙값/최대와 비교값을 함께 남긴다. 적 사망으로 노출 시간이 달라진 경우를 표시한다. 격차의 원인/개선 제안은 관측값과 구분하고, 합의 전 통과 임계값을 만들지 않는다.

- 정책 이름·버전·소스 SHA / 공개 관측 필드 목록 / 결정 간격·타이브레이크·탐색 예산:
- 미래 RNG·경기 seed·숨은 스폰이 정책에 노출되지 않았다는 확인 방법:
- 정책 RNG와 경기 RNG 분리 / 정책 seed / 실제 명령열·draw trace:
- 정책별 모든 run의 승패·도달 웨이브·누수·HP·재화 사용/잔액·공격시간 원자료:
- 같은 seed별 paired 차이 / 예외·탈락 run·이유 / 사전 목록과 실행 목록 차이:
- 해석 한계: 무작위는 sanity check, 일반/숙련은 고정 정책 비교, 재미의 증거가 아님

## 6. 배정·리뷰·통합 유효성 행렬

| 대상 | 현재 assignment-generation / owner | 대상 SHA | 실제 검토자·독립성 근거 | 읽은 diff·실행 범위/증거 | 결론·링크 | 현재 유효 여부 |
|---|---|---|---|---|---|---|
| #5 계획 문서 | 1 / 키키 | 미커밋 | 리더: 검토 대기 | 미실시 | pending | 승인 없음 |
| #5 계획 문서 | 1 / 키키 | 미커밋 | 모모: 검토 대기 | 미실시 | pending | 승인 없음 |
| 게임 구현 PR | 별도 배정 필요 | 미생성 | 미배정 | 미실시 | pending | 승인 없음 |
| 실제 통합 검증 | 해당 배정 기록 | 미통합 | 실제 검증자 기록 | 미실시 | pending | verified 아님 |
| 릴리스 검증 | 해당 시 기록 | 미릴리스 | 실제 검증자 기록 | 미실시 | N/A: 릴리스 없음 | 릴리스 주장 없음 |

- 리뷰 대상 이전 SHA→현재 SHA / diff 링크 / 재확인 시각:
- 최신 Issue 세대·owner·범위 확인 / main 이동·충돌·재개 승인 영향:
- 각 리뷰어가 실제 읽은 문서/이미지/코드와 실행한 검사, 못 본 부분:
- 필요한 독립 리뷰 수 / 아직 없는 리뷰 / 승인 철회·변경 요청:
- PR 검사 SHA와 통합 SHA 차이 / 통합 SHA 재실행 결과:
- 현재 단계: proposed / ready / assigned / in_progress / review / changes_requested / accepted / integrated / verified / blocked 중 근거와 함께

새 구현 SHA는 기존 승인을 무효화한다. 동료가 diff를 실제 검토하고 현재 SHA에 재확인하기 전 승인 칸을 복사하지 않는다. 같은 GitHub 계정의 actor 표기만으로 독립 리뷰를 증명하지 않으며 작성자/내부 보조 작업을 다른 닷의 리뷰로 세지 않는다. integrated는 verified가 아니다.

## 7. 차단과 인계

| 차단/미실시 | 정확한 원인·실패 증거 | 영향받는 사례 | 필요한 계약/환경/결정 | 담당·다음 확인 |
|---|---|---|---|---|
| 미기입 | 미기입 | 미기입 | 미기입 | 미기입 |

- 최종 변경 파일 / 전체 SHA / 실행 결과 요약:
- 유지된 제한·남은 위험 / 미실시와 이유:
- 다음 체크포인트 / 재개 때 다시 읽을 Issue·세대·main:

다른 사람이 같은 SHA·규칙·seed·명령열로 결과를 재현할 수 있는지 마지막으로 확인한다. 수행하지 않은 검사·사람 피드백·독립 승인을 채워 넣지 않는다.
